# Sanchar frontend: review and flow check

Scope: Instagram login, then dashboard, then conversations per channel, then messages. I read every file on that path and ran `npx tsc --noEmit --incremental false`, which passes with no errors. I did not run the app. Anything that depends on the FastAPI backend is marked **[backend]**. I could not see it.

## Verdict

The pieces exist: Instagram login link, cookie session, proxy, dashboard page, 5-second inbox polling, message view, media rendering, and WhatsApp linking. The flow you described does not hold together yet, for five reasons:

1. Login never sends the user to the dashboard.
2. A dead backend or expired session can put the browser in an infinite redirect loop.
3. The Channels screen and the inspector panels show invented data as if it were live.
4. Middleware breaks every static file for logged-out visitors, which matters for your SEO plans.
5. The "take over" button does nothing on the server.

Fixes below prefer one change at a choke point over many patches, so the flow stays correct when you add pages.

## Findings, most severe first

### S1. The user never lands on the dashboard

`middleware.ts:22`, `login/page.tsx:37`, and the OAuth callback redirect all end at `/`, the inbox.

There are two readings of this. Changing the redirects to `/dashboard` is small, but the Instagram path is decided by the backend **[backend]**, so the frontend cannot fully control it. Making `/` a redirect is also small, but it collides with the plan for a public landing page at `/`.

The version that keeps both: give the inbox its own URL and make the post-login target a single constant.

```ts
// middleware.ts  (replace lines 19-23)
const POST_LOGIN = '/dashboard';
const hasSession = req.cookies.has('ns_session');
const isLogin = pathname === '/login';
if (!hasSession && !isLogin) return NextResponse.redirect(new URL('/login' + search, req.url));
// Bounce a signed-in user off /login, but never when it carries a query
// (?ig_error=…, ?expired=1) — see S2.
if (hasSession && isLogin && !search) return NextResponse.redirect(new URL(POST_LOGIN, req.url));
// Backend callbacks that still redirect to "/" land on the dashboard too.
// Delete this line the day "/" becomes the public landing page.
if (hasSession && pathname === '/') return NextResponse.redirect(new URL(POST_LOGIN, req.url));
return NextResponse.next();
```

Also:
- Move `app/page.tsx` to `app/inbox/page.tsx`.
- In `PageHeader.tsx:37` and `:40`, and in `App.tsx:118` (`replaceState(null,'','/')`), change `/` to `/inbox`. Otherwise "INBOX" would bounce back to the dashboard.
- `login/page.tsx:37`: `assign('/dashboard')`.
- Ask the backend to redirect the Instagram callback to `/dashboard` as well. The middleware line above only covers you until then.

### S2. Redirect loop when the backend is down or the session is dead

This one bites in development, because the backend restarts often.

- `App.tsx:54-62` and `PageHeader.tsx:27-31` sign the user out on any failure of `getMyTenant`. `api.ts:25` throws on any non-OK status, including a 500/502 from a down backend, not just a 401.
- `signOut` calls `logout()`. If the proxy returns 502, `fetch` still resolves, so `assign('/login')` runs.
- Because the httpOnly cookie is still there, `middleware.ts:22` bounces `/login` back to `/`. The page mounts, calls `getMyTenant`, fails, and the cycle repeats. It is a full-page-load loop with no delay.
- A related problem: if a user with a live cookie hits `/login?ig_error=…` after a failed re-link, line 22 discards the error message.

Fix in two parts. The middleware change is in S1 (`!search`). In `api.ts`:

```ts
export class AuthError extends Error {}
export async function getMyTenant(): Promise<Tenant> {
  const res = await fetch('/api/v1/tenants/me');
  if (res.status === 401 || res.status === 403) throw new AuthError('Not authenticated');
  if (!res.ok) throw new Error(`Backend unavailable (${res.status})`);
  return res.json();
}
```

In `App.tsx` and `PageHeader.tsx`, only sign out on `AuthError`. For any other error, show a banner and keep polling. In `signOut`, send the user to `/login?expired=1`.

**[backend]** Whether `/auth/logout` clears the cookie when the session is already invalid is unknown. The `?expired=1` bypass makes the loop impossible either way.

### S3. Every non-Instagram-looking part of "Channels" is invented

- `MetaSettingsModal.tsx:175-229` shows Facebook as "LINKED & ACTIVE" with a fake page, and Instagram as "VERIFIED" with `@himalayan_silk_np`. Both come from `mockData.ts:229-248`.
- Only the WhatsApp card is real (`getWhatsAppAccounts`).
- Instagram data is available for real: `getInstagramProfiles()` (`api.ts:149`) already backs `ProfileModal`. Reuse it here.
- Facebook has no backend call, so render it as "Not connected" until one exists.
- There is no "Connect Instagram" or "Connect Facebook" button anywhere in the app. Instagram can only be linked from `/login`. Your stated goal is "link or login from the desired social media", so a tenant who signed up by email has no way to add Instagram.
- **Stale name bug** (`MetaSettingsModal.tsx:61`): `useState(businessName)` runs once, when `App` first renders, with the hardcoded `'Himalayan Silk & Handicrafts (काठमाडौँ)'` (`App.tsx:25`). The real tenant name arrives later. The modal stays mounted, so the input keeps the mock name. "Save Configuration" (`:114-117`) then overwrites the real name in the header with the mock one. Nothing is sent to the backend either, so the save is cosmetic. Fix:
  ```ts
  useEffect(() => { if (isOpen) setBName(businessName); }, [isOpen, businessName]);
  ```
  Change `App.tsx:25` to `useState('')`, or remove the Save button until a `PATCH /tenants/me` exists.
- `:62` (`socialsync_meta_wh_sec_991823`) and `:401` (`api.socialsync.np/v1/meta/webhook`) are fake. "PING WEBHOOKS" (`:105-112`) is a `setTimeout` that prints "HTTP 200 OK — Verified". That is a green light that lies. Remove it. The real WhatsApp PING above it already checks the webhook subscription.
- `RightInspector.tsx:182-213`: the "ACTIVE CHANNELS" stamp and "Meta Webhooks 200 OK" are static. `PageHeader.tsx:38` imports the mock `initialMetaStatus` just to satisfy a prop that `Header` never reads (`Header.tsx:65-74` does not destructure `metaStatus`). Delete that prop chain.

### S4. Middleware now breaks static files (regression from `middleware.ts.bak`)

`middleware.ts:27` matcher: `'/((?!api|_next|favicon.ico).*)'`. The `.bak` version had `|.*\\..*`, which is gone. So `/robots.txt`, `/sitemap.xml`, `/sanchar-mailbox.svg`, any `og:image`, and all of `public/` get a 307 to `/login` for logged-out visitors. That includes crawlers. This directly hurts the SEO goal.

```ts
matcher: ['/((?!api/|_next/|.*\\..*).*)', '/api/v1/:path*'],
```

Two side effects worth knowing: `/` redirects crawlers to `/login` (fine for now), and `/login` is the only indexable page. It has no page-specific title or description, and it is a client component, so it cannot export `metadata`. When SEO becomes real, split the marketing content into a server component and keep only the form as a client component.

### S5. "Take over" and "Resolve" do nothing on the server

`App.tsx:122-139` only edits local state. `App.tsx:73-75` replaces `status` from the server's `mode` every 5 seconds, so the toggle reverts. The AI may keep replying while an operator types. It needs `PATCH /conversations/{id}` with `{mode}` **[backend: the endpoint may not exist]**. Until then, disable the button with a "coming soon" note, because a switch that visibly flips and then silently flips back is worse than none.

### S6. Message view labels real messages wrongly

- `api.ts:85`: `sender_type` `'system'` and `'agent'` both become `'human'`, so system notes show as "Human Operator (Merchant)" with "OPERATOR OVERRIDE SENT VIA GRAPH API" (`InboxFeed.tsx:369`). Map `system` to its own style.
- `InboxFeed.tsx:329-334`: real AI messages have no `confidence` or `source`, so every one shows `CONFIDENCE: 0.00` and `SOURCE:` with nothing after it. Render each badge only when the value exists.
- `InboxFeed.tsx:316`: "SocialSync AI (RAG-Enabled)" is the old product name.
- `SidebarNav.tsx:455`: `CONF: 0.00` on every real thread (`confidenceScore` is never set by `toThread`). Same fix.
- `SidebarNav.tsx:398,437`: previews use `thread.messages`, but `App.tsx:74` only loads messages for the open thread, so every other thread reads "No messages yet". Show the backend's last-message preview **[backend: the field may need adding to `/conversations`]**, or show nothing.
- `api.ts:80`: timestamps are time-only, so messages from different days look the same. Include the date when it is not today.
- `InboxFeed.tsx:28`: the alt text "Image expired — view in Instagram" is used for WhatsApp images as well.
- `RightInspector.tsx:72`: for real threads `ragSourceDoc` is undefined, so an empty badge shows. `detectedIntent` renders blank as well.

### S7. Dashboard: works, but thin and misleading

- The window is fixed to 1 day (`api.ts:129`, `dashboard/page.tsx:102`). Add a 1/7/30-day selector; the API already takes `days`.
- Shows WhatsApp, Instagram, and Facebook rows always (`dashboard/page.tsx:87`). A fresh Instagram-only user sees zeros for the other two and no call to connect them. Add an empty state that links to Channels.
- `escalations` (`:109`) sums `handover` over the window. The inbox badge counts threads currently in `NEEDS_HUMAN`. Same label, two meanings. Label the dashboard one "Handovers (24h)".
- The response is trusted blindly. If `new_messages` is missing, `counts[ch]` throws and the page crashes with no error boundary. Guard with `?? {}` and `?? 0`.
- The first Instagram login makes this the first screen the tenant sees, so a loader with no retry button on failure feels broken. Add a retry.

### S8. Dev-only features that look real

- The `+ INBOUND` button (`Header.tsx:188`), `SIMULATE CUSTOMER` (`InboxFeed.tsx:198`), `RAGSandboxModal`, and `AI DRAFT` all call `/api/v1/ai/reply`, which the comment at `api.ts:41` says 404s. Simulated threads are deleted by the next poll (`App.tsx:73-75` rebuilds from the server list).
- `InboxFeed.tsx:118-121`: when AI DRAFT fails, it types a fake Nepali apology into the reply box, so a merchant might send it to a customer. Show an error instead.
- Catalog, FAQs, the discount policy, and delivery prices in `RightInspector.tsx:93-118` are hardcoded mock data.
- The footer's token usage and latency are invented (`App.tsx:99-100`).
- `alert()` on send failure (`App.tsx:155`).

Guard all of these behind one flag so they can be switched back on: `NEXT_PUBLIC_DEV_TOOLS=1`.

## Cleanup and exposure

- **`app/api/meta/*` is public.** The matcher skips `api`, so login is not required. `webhook-logs` GET returns stored payloads to anyone, and `webhook` POST accepts unauthenticated, unsigned writes. It is dead code, since real webhooks go to FastAPI. Delete the folder. `app/api/health/route.ts` still says "SocialSync" and `hasGeminiKey`; keep it only if a load balancer uses it, and drop the key check.
- Delete `app/api/amit/page.tsx` (an empty page at `/api/amit`), `middleware.ts.bak`, `public/assets/aistudio/` (empty), and `public/sanchar-mailbox.svg` if unused (I found no references).
- `tsconfig.tsbuildinfo`, `middleware.ts.bak`, and `conversation_example.json` are already in `.gitignore`, and `git ls-files` shows none of them tracked. No action needed.
- `login/page.tsx:~245`: "terms of service" and "privacy policy" are plain `<span>`s. Meta app review needs a public privacy-policy URL, and a data-deletion URL or callback for Instagram and Facebook login. Add real routes, for example `/privacy` and `/data-deletion`, which are also good indexable pages.
- `login/page.tsx:96` and the footer make claims ("100% Sulphur-Free", "GDPR / Nepal Telecomm Ready", "Free forever for core features", "Graph API v21.0") that you would not want reviewers to read as compliance statements. Remove the compliance ones.
- `Dockerfile` and compose: `BACKEND_URL` defaults to `http://localhost:8000` (`middleware.ts:3`), which inside a container points at the container itself. If `.env` lacks `BACKEND_URL`, every API call fails with no warning. Fail loudly at startup in production, or add it to `.env.example` **[unchecked: `.env.example` content]**.
- The polling in `App.tsx:80` keeps running in background tabs and hides errors in `console.error`. Pause it when `document.hidden`, and show an "offline" banner after 2 failures.
