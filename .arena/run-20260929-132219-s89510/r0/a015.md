# Sanchar frontend: Instagram login -> dashboard -> conversations

I read every file in the flow. `npx tsc --noEmit` passes. I did not run it against your backend. Findings that depend on backend behaviour are marked **[backend]**.

## Verdict

The pieces work, but they do not add up to the flow you described.

- **What works:** Instagram login, the cookie session, the inbox with real DMs, sending a reply, the connected-channel modals, and a real `/dashboard` endpoint.
- **What diverges from your flow:**
  1. A new user lands on the inbox, not the dashboard.
  2. The dashboard has no conversation list, so it is a different screen from the one you described (dashboard plus per-social-media list on the left).
  3. Several screens show fake "everything is connected and healthy" status. During testing this will make you doubt real bugs, and in a Meta app-review demo it is a liability.

## Assumptions

- "Dashboard with all metrics" means `/dashboard` (`getDashboard`), not the Instagram profile card.
- "Conversations listed per social media" means the inbox sidebar (`SidebarNav`) with its IG/WA/FB filter. It is a filtered flat list, not grouped sections. I treat that as acceptable.
- The backend's Instagram OAuth callback redirects to `/`. I cannot see it, so this is a guess.

## Blocking the flow (fix first)

1. **Login lands on the inbox, not the dashboard.**
   - Both entry paths go to `/`: `middleware.ts:22` (session on `/login`) and `app/login/page.tsx:37` (email login).
   - The Instagram path also depends on **[backend]** where the callback redirects.
   - Frontend-only fix: change both to `/dashboard`. The Instagram case still needs the backend callback to redirect to `/dashboard`.
   - If you can't touch the backend, move the inbox to `/inbox` and make `/` the dashboard. Then any redirect to `/` works, and it also gives you the public-`/` SEO layout below.

   ```diff
   - if (hasSession && isLogin) return NextResponse.redirect(new URL('/', req.url));
   + if (hasSession && isLogin) return NextResponse.redirect(new URL('/dashboard', req.url));
   ```
   ```diff
   - window.location.assign('/'); // full load so middleware sees the new cookie
   + window.location.assign('/dashboard'); // full load so middleware sees the new cookie
   ```

2. **The middleware matcher regressed, so static and SEO files redirect to login.**
   - `middleware.ts:27` is `'/((?!api|_next|favicon.ico).*)'`.
   - `middleware.ts.bak` had `|.*\\..*` in the exclusion. Without it, `/robots.txt`, `/sitemap.xml`, `/og.png` and everything in `public/` redirect logged-out visitors to `/login`.
   - That defeats the SEO goal.
   - Fix: `matcher: ['/((?!api|_next|.*\\..*).*)', '/api/v1/:path*']`. The dot rule already covers `favicon.ico`.

3. **A transient error logs the user out.**
   - `App.tsx:61` and `PageHeader.tsx:30` run `.catch(handleSignOut)` on any failure of `getMyTenant`. That includes a 500, a backend restart or a dropped network, not just a 401.
   - `getMyTenant` (`api.ts:25`) throws the same error for all of them.
   - Fix: sign out only on 401. Throw a typed error from `api.ts`, or check `res.status === 401`.
   - **[backend]** `logout()` (`api.ts:13`) ignores its response. If the backend won't clear `ns_session` for an already-expired session, `/login` and `/` will bounce off each other in a redirect loop. Test this once with an expired cookie.

## Wrong behaviour on real data

4. **Real AI messages show fake metadata.**
   - Real AI messages have no `confidence` or `source`, because `toChatMessage` (`api.ts:83`) never sets them.
   - `InboxFeed.tsx:330` renders `CONFIDENCE: 0.00` (the `?? 0`) and `SOURCE:` with an empty value.
   - The label at `:316` says "SocialSync AI (RAG-Enabled)", which is the old product name.
   - Fix: render the confidence and source badges only when the values exist, and rename the label to "Sanchar AI".
   - The sidebar has the same problem: `SidebarNav.tsx:208` shows `CONF: 0.00` on every real thread. Hide it when `confidenceScore` is undefined.

5. **Human takeover is fake.**
   - `handleToggleTakeover` (`App.tsx:122`) only edits local state. The next 5-second poll rewrites `status` from the server's `mode` (`api.ts:102`), so the button reverts.
   - Worse, the escalation banner and the "AI suspended" text imply the AI has stopped. **[backend]** It probably hasn't.
   - It needs a PATCH endpoint to change the conversation mode. Until then, disable the button or label it "not wired".

6. **Sidebar previews are empty for every thread except the open one.**
   - Messages are fetched only for the active thread (`App.tsx:89`), so all others show "No messages yet" (`SidebarNav.tsx:190`).
   - This makes "conversations listed per social media" look empty.
   - **[backend]** Have `/conversations` return `last_message`.

7. **Sender labels are wrong.**
   - `toChatMessage` maps both `agent` and `system` to `human`.
   - `InboxFeed.tsx:359` and `:370` label every such message "Human Operator (Merchant)" and "OPERATOR OVERRIDE SENT VIA GRAPH API", including system notes.
   - **[backend]** I can't see whether `system` messages occur.

8. **The AI DRAFT failure path puts a fake reply in the input.**
   - `askAi` calls `/api/v1/ai/reply`, which the code itself says 404s (`api.ts:41`).
   - The catch in `InboxFeed.tsx:120` fills the reply box with a hard-coded "Hamro store bata hajur ko query review..." message.
   - The operator can then send that to a real customer with one click.
   - Fix: show an error and leave the input alone.

9. **Send failure uses `alert()` (`App.tsx:155`).** Show an inline error instead.

10. **The active conversation can be hidden by the filter.**
    - Selecting the WA filter while an IG thread is open leaves the IG thread showing in the centre pane, but not in the list.
    - Either clear the selection or say "filtered out".

## Dashboard (`app/dashboard/page.tsx`)

- It is text-only counts: four blocks, no charts or trend. Compared with "all the metrics available" it is thin.
- The window is fixed at `getDashboard(1)`. `api.ts:129` accepts `days`, but there is no selector.
- It always lists WhatsApp, Facebook and Instagram (`:19`). A new Instagram-only tenant sees a wall of zeros and no "connect a channel" prompt. Show only connected channels, and add an empty state linking to Channels.
- The escalation badge (`:41`) sums the `handover` counts over the window. The inbox badge counts threads currently in `NEEDS_HUMAN`. These are two different numbers under one label.
- The Instagram numbers that exist (followers, follows, posts) are hidden in `ProfileModal`, behind the avatar button. Consider showing them on the dashboard.
- **[backend]** The response is trusted. If a channel key is missing, the page shows `undefined`. Use `counts[ch] ?? 0`.

## Security and cleanup

- **`app/api/meta/webhook`, `webhook-logs` and `test-connection` are publicly reachable.**
  - The matcher excludes `/api`, so they skip the login redirect.
  - `webhook` accepts any POST with no HMAC check and stores it in memory.
  - `webhook-logs` returns the stored payloads to anyone.
  - `test-connection` always returns success.
  - Delete `app/api/meta/`. Your real webhook goes to FastAPI.
- **`app/api/health`** mentions Gemini and "SocialSync". Make it return only `{status:'ok'}`.
- **Leftover files:** `app/api/amit/page.tsx` (returns null), `middleware.ts.bak`, `tsconfig.tsbuildinfo` (tracked), and `conversation_example.json` (real Instagram IDs and usernames in git). Remove them.
- **Terms and privacy** on the login page (`:246,248`) are `<span>`s, not links. Meta app review needs a real privacy policy URL and a data-deletion URL.
- **Login page** shows "Meta Graph v21.0 Compliant" and "GDPR / Nepal Telecomm Ready". These are claims nobody has checked.
- **Deploy:** `.env.example` sets `BACKEND_URL=http://api:8000`, which fits the external `nepsocial` network. Without it the middleware falls back to `localhost:8000`, which is wrong inside the container.

## SEO

- `/` and `/dashboard` are private and `ssr:false`, so only `/login` is indexable.
- One global title and description in `layout.tsx` applies to every page, and there is no `robots`, `sitemap` or canonical.
- The clean fix: a public marketing page at `/` (server-rendered, own metadata), the inbox at `/inbox`, and `/login` with its own metadata. Do this together with fix 1 above.
- Fonts are loaded through a `<link>` in `<head>`. `next/font` avoids the render-blocking request.
