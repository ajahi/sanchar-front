# Sanchar frontend: review and flow check (Instagram login -> dashboard -> conversations)

I read every file in the flow (middleware, login, dashboard, inbox `App.tsx`, `api.ts`, all components, `app/api/**`, Docker files). Nothing was run against a backend. Findings that depend on FastAPI behaviour are marked **[backend?]**. Line numbers are per file.

## Verdict in one paragraph

The pieces exist and are wired to real endpoints: Instagram OAuth link, session cookie, dashboard, conversation list, message thread, send reply. Two things break the flow you described.

1. After login the user lands in the inbox, not the dashboard.
2. The screens around the real data still show hard-coded demo values as if they were live: "Himalayan Silk" as the connected account, "LINKED & ACTIVE", "Webhooks 200 OK", fake webhook URL and secret.

Together these make it hard to tell what is working while you test. Fixes are listed below in priority order.

## A. Blocks or breaks the flow (fix first)

1. **Lands on the inbox, not the dashboard.** See above. Severity: high. `middleware.ts:22`, `login/page.tsx:37`, and the backend callback **[backend?]**.

2. **Static and public files redirect to `/login` for logged-out visitors.** The matcher is `'/((?!api|_next|favicon.ico).*)'` (`middleware.ts:27`). The old `middleware.ts.bak` excluded `.*\\..*`. Now `/robots.txt`, `/sitemap.xml`, `/sanchar-mailbox.svg`, `/assets/*` and OG images all get a 302 to `/login`. Meta's crawler and Google will not see them. Fix: `matcher: ['/((?!api|_next|.*\\..*).*)', '/api/v1/:path*']`.

3. **A transient error signs the user out.** `App.tsx:54-61` and `PageHeader.tsx:28-30` run `getMyTenant().catch(signOut)`. `getMyTenant` throws on any non-2xx, including a 500 or a backend restart, so a backend blip during testing logs the user out. Worse, `signOut` awaits `logout()`, which throws if the network is down. The user is then left on an empty inbox with the cookie still set. Fix: sign out only on 401, otherwise show a "retry" state.
   ```ts
   // api.ts
   if (res.status === 401) throw new Error('unauthenticated');
   ```
   ```ts
   // App.tsx and PageHeader.tsx
   .catch((e) => e.message === 'unauthenticated' && handleSignOut())
   ```

4. **Session expiry after mount is never handled.** The 5s poll (`App.tsx:80`) only does `console.error`, so it keeps hammering a dead session and the list freezes. Make `listConversations` throw `unauthenticated` on 401 and use the same handler.

5. **`BACKEND_URL` in the container [backend?]/config.** `middleware.ts:3` defaults to `http://localhost:8000`. Inside Docker that address is wrong, so every `/api/v1/*` call would 500 with no hint. `.env` is in `.dockerignore` and supplied at runtime by `env_file`. Check that middleware actually sees it: from the running container, `curl localhost:3000/api/v1/tenants/me` should return a 401 JSON, not a 500. If it does not, read the variable through `next.config.ts` `rewrites()` or set it at build time.

6. **Meta webhooks 404 unless nginx sits in front.** `middleware.ts:11-13` lets `/api/v1/webhooks/*` fall through to Next, which has no such route. `docker-compose.yml` publishes only port 3000 and has no nginx. If you test through a tunnel to `:3000`, Meta's callbacks get a 404. Point the Meta webhook at FastAPI directly, or add the nginx rule. (The comment's claim that a Next rewrite breaks HMAC is unverified. Test it before relying on it.)

## B. Real bugs in the inbox and dashboard

7. **Human takeover does not persist.** `handleToggleTakeover` (`App.tsx:122`) only edits local state. Within 5s `toThread` (`api.ts:102`) resets `status` from `c.mode`. The buttons "TAKE OVER AS HUMAN" and "RESOLVE & RE-ENABLE AI" look functional and do nothing on the server. Either add a backend PATCH and call it, or disable the buttons with a "coming soon" label. **[backend?]**

8. **Renaming the business writes the demo name back.** `MetaSettingsModal.tsx:61` does `useState(businessName)`. The modal is mounted from first render, when `businessName` is still the placeholder `'Himalayan Silk & Handicrafts…'` (`App.tsx:25`). The real tenant name arrives later, but `bName` never re-syncs. Clicking "Save Configuration" (`:114`) then overwrites the header with the fake name. The save is also local only, so a reload loses it. Fix: `useEffect(() => setBName(businessName), [businessName, isOpen])`, and either persist it or remove the field.

9. **Enter sends while composing Nepali text.** `InboxFeed.tsx:103` sends on `Enter` with no `e.nativeEvent.isComposing` check. Confirming a Devanagari IME candidate with Enter sends a half-typed reply to a real customer. Also `handleSend` clears the input first (`:99`) and failures only `alert()` (`App.tsx:155`), so the text is lost. Fix: skip when `isComposing`, clear the input only after `sendReply` resolves, and show an inline error.

10. **Sidebar previews are blank for every thread except the open one.** `SidebarNav.tsx:190` shows "No messages yet" because messages load only for the active thread. The list DTO has no last-message text (`ConversationDto`, `api.ts:59`). Ask the backend for `last_message_preview` **[backend?]**.

11. **Every real thread shows `CONF: 0.00` and empty AI metadata.** `SidebarNav.tsx:208` and `InboxFeed.tsx:330-333` render `(x ?? 0).toFixed(2)` and `SOURCE: {source}`. The API supplies neither, so every AI message shows "CONFIDENCE: 0.00, SOURCE:" blank. Render the badges only when the value exists. The same applies to the right panel: "DETECTED INTENT" and "KNOWLEDGE BASE SOURCE" are blank (`RightInspector.tsx:41`, `:72`).

12. **Sender labels are wrong for `agent` and `system` messages.** `api.ts:85` maps anything not customer or ai to `human`, so a `system` event renders as "Human Operator (Merchant) - OPERATOR OVERRIDE SENT VIA GRAPH API" (`InboxFeed.tsx:370`). Add a `system` branch.

13. **Timestamps carry no date.** `fmtTime` (`api.ts:80`) returns HH:MM only. A thread from last week shows "02:15 PM", and messages across several days cannot be told apart. Show the date when it is not today.

14. **Dashboard is thinner than "all metrics".**
    - `getDashboard()` is called with no argument (`dashboard/page.tsx:34`), so the window is fixed at 24h. The backend already accepts `days`. Add a 1/7/30 selector and a refresh button.
    - It always lists WhatsApp, Facebook and Instagram (`:8-12`), so a tenant who just logged in with Instagram sees zeros for two channels with no "connect" prompt. Show only connected channels, or show an empty state linking to Channels.
    - The connected-account stats (followers, following, posts) exist in `getInstagramProfiles` but appear only inside the profile pop-up. Put a card on the dashboard.
    - The header badge (`:41`) sums handover counts over the window, while the inbox badge counts threads currently `NEEDS_HUMAN`. Two different numbers under one label.
    - The response is trusted: `counts[ch]` renders `undefined` if a channel key is missing. Default with `?? 0`.
    - The error state has no retry and no way back.

15. **No unread markers, no sorting guarantee.** `toThread` never sets `unreadCount`, and the list is shown in backend order. Sort by `lastMessageAt` descending on the client.

## C. Mock or placeholder content that misleads

16. **Channels modal shows fake connection state** (`MetaSettingsModal.tsx`):
    - Facebook "LINKED & ACTIVE" with a fake page (`:187`, from `initialMetaStatus`, `mockData.ts:229-248`).
    - Instagram "VERIFIED" with `@himalayan_silk_np` (`:215`, `:222`). The real account is available from `getInstagramProfiles`.
    - "PING WEBHOOKS" (`:105`) is a `setTimeout` that always prints "HTTP 200 OK - Inbound Webhooks Verified".
    - The displayed callback URL `https://api.socialsync.np/v1/meta/webhook` (`:401`) and verify token `socialsync_meta_wh_sec_991823` (`:62`) are fake and do not match the real `/api/v1/webhooks/…` route. Someone who copies them into the Meta dashboard will fail verification.
    - Only the WhatsApp card is real, and it is done well: it shows the three real checks.
    Fix: build the Instagram and Facebook cards from the API, or show "Not connected" instead of demo values.

17. **`RightInspector.tsx`**: "RAG ACTIVE" (`:31`), "ACTIVE CHANNELS" with all three logos lit and "Meta Webhooks 200 OK" (`:185-211`) are static. The catalog list, delivery fees and discount policy are mock (`mockData.ts`).

18. **Footer and fake numbers** (`Footer.tsx`, `App.tsx:99`): token usage 412/10000, latency 120 ms, "Meta Graph API v21.0 ACTIVE", "SYSTEM ID: SS-AI-KATHMANDU-01". Also "Meta 24h Window: Active" (`InboxFeed.tsx:163`) and "Encryption: E2E Verified" (`:433`) are constants. The 24h window is real Meta policy and should be computed from the last customer message, otherwise a send after expiry fails with only an alert.

19. **Simulator and sandbox are dead against this backend.** `+ INBOUND` (`Header.tsx:150`), "SIMULATE CUSTOMER" (`InboxFeed.tsx:205`), "AI DRAFT" and the RAG sandbox all call `/api/v1/ai/reply`, which is marked as not existing yet (`api.ts:41`). Simulated threads are wiped by the next poll. "AI DRAFT" falls back to a canned Nepglish apology (`InboxFeed.tsx:120`) that can end up in the reply box. Hide these behind `process.env.NEXT_PUBLIC_DEV_TOOLS`.

20. **Catalog/FAQ editing is in-memory only** (`App.tsx:29-30`). Data vanishes on reload.

21. **Brand leftovers**: "SocialSync AI (RAG-Enabled)" on every AI bubble (`InboxFeed.tsx:316`), "SOCIALSYNC AI" in the footer, "Ask Gemini…" tooltip (`:415`). `app/api/health/route.ts` returns `service: 'SocialSync…'` and reports `hasGeminiKey`.

## D. Cleanup, security and Meta app review

22. **`app/api/meta/*` is dead and public.** Nothing in `src/` or `app/` calls it. The matcher skips `/api/*`, so `webhook` (POST, no HMAC check) and `webhook-logs` (GET, returns stored payloads) are reachable by anyone. `test-connection` always returns `CONNECTED`. Delete the folder. Also delete `app/api/amit/page.tsx` (an empty page under `api/`) and untrack `middleware.ts.bak`, `tsconfig.tsbuildinfo` and `conversation_example.json` (real Instagram usernames and IDs in git).

23. **Terms and privacy are plain `<span>`s** (`login/page.tsx:246-247`). Meta app review needs a public privacy-policy URL and a data-deletion URL. Build `/privacy`, `/terms` and a deletion page. They must be reachable logged-out, so fix item 2 first.

24. **Marketing claims on the login page** ("FREE FOREVER", "Meta Graph v21.0 Compliant", "GDPR / Nepal Telecomm Ready") are unbacked. Remove them before review. "By signing up" sits above a login-only form, and Instagram-created tenants probably have no password **[backend?]**.

25. **SEO groundwork** (later, but cheap now):
    - Only `/login` is indexable, since everything else redirects. Fine for now.
    - `layout.tsx:12` sets `twitter: summary_large_image` with no image, and there is no `metadataBase`, `robots.ts` or `sitemap.ts`.
    - Five Google font families are loaded with a render-blocking `<link>` (`layout.tsx:22`). Use `next/font`.
    - The inbox is `ssr:false` (`app/page.tsx`). Correct for a private app; keep it off the public routes.
    - Give the public landing page `/` (after option B) its own metadata.

26. **Accessibility basics on login**: `<label>`s have no `htmlFor` (`login/page.tsx`), the whole page is `select-none`, and sidebar cards are clickable `div`s with no keyboard support (`SidebarNav.tsx:158`). Use `<button>`.

27. **Minor**: `Header.tsx` never uses its `metaStatus` prop, and `PageHeader.tsx:38` still passes the mock. "LOGIN / SIGN UP" flashes while the user loads and its handler is undefined (`Header.tsx:187`). `app/loading.tsx` uses a blue spinner that does not match the brand loader. `SidebarNav.tsx:67` "N ACTIVE" ignores the filter. `top_queries` uses `q.text` as a React key.
