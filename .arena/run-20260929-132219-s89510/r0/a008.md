# Sanchar frontend: review and flow check (Instagram login -> dashboard -> conversations)

## Verdict

The real path works and typechecks (`npx tsc --noEmit --incremental false` gave no errors). That path is: session cookie -> `/api/v1` proxy -> tenant -> conversation list -> messages -> send reply. Four things stop it from being the flow you described:

1. **A new tenant does not land on the dashboard.** It lands on the inbox, or wherever the backend's OAuth callback redirects.
2. **A dead session or a down backend can trap the user in a redirect loop.** This will happen often while you restart the backend during testing.
3. **A signed-in tenant cannot connect Instagram or Facebook from inside the app.** The Channels screen shows a made-up Instagram and Facebook connection as "VERIFIED / LINKED & ACTIVE".
4. **Several screens show made-up values as if they were real.** These are the business name, the AI confidence and source on real messages, and the timestamps.

Dashboard-first is a small change (Fix 1). Everything marked "backend" below depends on FastAPI code I cannot see.

## Fix these first (the flow is blocked or looping)

### 1. Make the dashboard the landing page, whatever the backend does

The backend probably redirects to `/`, so changing the callback alone is fragile. Make `/` forward to `/dashboard` for signed-in users and move the inbox to `/inbox`. Then every entry path (Instagram callback, email login, the `/login` bounce) ends on the dashboard.

- Move `app/page.tsx` to `app/inbox/page.tsx`. Change its two imports from `'../src/...'` to `'../../src/...'`.
- `middleware.ts`:
```ts
if (!hasSession && !isLogin) return NextResponse.redirect(new URL('/login' + search, req.url));
// don't swallow ?ig_error= when a stale cookie exists
if (hasSession && isLogin && !search.includes('ig_error'))
  return NextResponse.redirect(new URL('/dashboard', req.url));
if (hasSession && pathname === '/') return NextResponse.redirect(new URL('/dashboard', req.url));
```
- `login/page.tsx:37`: `window.location.assign('/dashboard')`.
- `PageHeader.tsx:37` and `:40`: `/` becomes `/inbox` and `/?tab=…` becomes `/inbox?tab=…`.
- `App.tsx:118`: `replaceState(null, '', '/inbox')`.

The existing `?tab=` handling in `App.tsx:113-119` keeps working.

**Middleware matcher.** `matcher: ['/((?!api|_next|favicon.ico).*)', …]` (line 27) no longer excludes files. The old `.bak` had `.*\\..*`. Nothing in `public/` is needed by logged-out pages today, so this is harmless now. But it will redirect `robots.txt`, `sitemap.xml` and OG images to `/login` the day you add them. Use `'/((?!api/|_next/|.*\\..*).*)'`. The `api/` (with the slash) also stops it swallowing a future `/apis` page.

### 2. Stop the sign-out redirect loop

There are two loops:

- **Backend down or restarting.** `App.tsx:54-61` and `PageHeader.tsx:28-30` treat any `getMyTenant()` failure as a dead session. The rewrite answers 502 or 500, so `fetch` resolves, and `logout()` (`api.ts:13-15`) never checks the response. `location.assign('/login')` runs, but the cookie is still there, so middleware sends `/login` back to `/`, and the cycle repeats. If `fetch` itself rejects, `handleSignOut` throws before it redirects, and the user sits on the inbox with the mock name "Himalayan Silk".
- **Invalid cookie.** This loop happens only if the backend's logout does not clear the cookie when the session is invalid. I cannot see that code.

Fix:

1. Have `getMyTenant` throw the status: `throw Object.assign(new Error('Not authenticated'), { status: res.status })`. Sign out only on 401. On any other status, show a "Can't reach the server, retry" banner and stay put.
2. Do the sign-out server-side, so it works even when the backend cannot clear the cookie. Add `app/logout/route.ts`:
```ts
import { NextRequest, NextResponse } from 'next/server';
const BACKEND_URL = process.env.BACKEND_URL ?? 'http://localhost:8000';
export async function GET(req: NextRequest) {
  await fetch(new URL('/api/v1/auth/logout', BACKEND_URL), {
    method: 'POST', headers: { cookie: req.headers.get('cookie') ?? '' },
  }).catch(() => {});                                   // best effort
  const res = NextResponse.redirect(new URL('/login', req.url));
  res.cookies.delete('ns_session');                     // assumes path=/ and no Domain attribute
  return res;
}
```
   Point `handleSignOut` in `App.tsx:47-50` and `signOut` in `PageHeader.tsx:22-25` at `window.location.assign('/logout')`.
3. The inbox poll (`App.tsx:78`) only calls `console.error`. If the cookie expires mid-session, the page freezes silently. Route 401s from `listConversations` and `listMessages` to the same sign-out. A small `apiFetch` wrapper in `api.ts` that checks for 401 is enough.

### 3. Add "Connect Instagram" and "Connect Facebook" to Channels

Right now the only Instagram entry point is the button on `/login`. A signed-in user cannot reach that page, because `middleware.ts:22` bounces them off it. `ProfileModal.tsx:68` even says "Log in with Instagram again to refresh", but there is no button.

- In `MetaSettingsModal`, replace the fake Instagram card (lines 204-229) with data from the existing `getInstagramProfiles()`, plus a `<a href={INSTAGRAM_LOGIN_URL}>Connect / reconnect Instagram</a>` link.
- Backend: confirm that the login endpoint, when called with a session cookie, attaches the account to the current tenant instead of creating a new one.
- Facebook has no API in this frontend and no backend call. Show "Not available yet" instead of "LINKED & ACTIVE".

## Wrong data shown as real (rank 2)

**4. The Channels screen and the header lie about connection state.** This is the most misleading thing a first-time tenant sees.
- `MetaSettingsModal.tsx:186` shows the Facebook card as "LINKED & ACTIVE" with the page "Himalayan Silk". Line 214 shows Instagram as "VERIFIED" with `@himalayan_silk_np`. These come from `initialMetaStatus` (`mockData.ts:229`, passed in at `App.tsx:31`). A user who just logged in as their own handle sees someone else's.
- **"PING WEBHOOKS"** (lines 105-112) is a `setTimeout` that always prints "HTTP 200 OK - Inbound Webhooks Verified". It never calls the network. It does not use `app/api/meta/test-connection` either.
- Line 401 shows the callback URL `https://api.socialsync.np/v1/meta/webhook`, which is not your real one (`/api/v1/webhooks/...`). Line 62 hard-codes a verify token that ships in the client bundle. If it is real, rotate it. If it is decoration, delete it.
- `RightInspector.tsx:182-212` has an "ACTIVE CHANNELS" stamp showing all three connected, plus "Meta Webhooks 200 OK". Lines 105-117 hard-code delivery fees and "VINTAGE5". The "Store Catalog" is `mockData`.
- Fix: derive the badges from the real `getInstagramProfiles()` and `getWhatsAppAccounts()` (which you already have). Delete the fake ping, the webhook card, and the stamp until they are backed by data.

**5. Saving Settings can overwrite the real business name with the mock one.**
- `App.tsx:25` initialises `businessName` to "Himalayan Silk & Handicrafts". `MetaSettingsModal` is always mounted and returns `null` after its hooks (line 101), so `useState(businessName)` (line 61) captures the mock string before `getMyTenant()` returns.
- Opening Channels and clicking "Save Configuration" (lines 114-117) then pushes the mock name back into the header.
- Even when the name is right, nothing is persisted. Save only sets local state, and the language choice is lost on reload.
- Fix: `useEffect(() => { if (isOpen) setBName(businessName); }, [isOpen, businessName]);`. Start `App`'s `businessName` at `''`. Hide the Save button until there is a PATCH endpoint.

**6. Real messages are drawn with fake AI metadata.**
- Backend messages never carry `confidence` or `source` (`api.ts:83-90`). `InboxFeed.tsx:330` prints "CONFIDENCE: 0.00" in a green badge on every real AI reply, and line 333 prints "SOURCE: " with nothing after it.
- Line 316 labels the sender "SocialSync AI (RAG-Enabled)", the old product name.
- `api.ts:85` maps both `agent` and `system` messages to `'human'`. `InboxFeed.tsx:353-371` renders those as "Human Operator (Merchant) ... OPERATOR OVERRIDE SENT VIA GRAPH API". System notes are therefore shown as something the merchant typed.
- Fix: render the confidence and source badges only when the values exist (`conf != null &&`). Add `'system'` to `ChatMessage.sender` and show it as a grey centred note. Rename the label to "Sanchar AI".
- `RightInspector.tsx:41` and `:72` render blank for `detectedIntent` and `ragSourceDoc` on every real thread.
- `InboxFeed.tsx:163` and `:433` claim "Meta 24h Window: Active" and "E2E Verified". Neither is computed. Real DMs outside the 24-hour window will fail on send (backend), so compute it from `lastMessageAt` or remove the claim.

**7. Times have no dates.**
- `api.ts:80-81` formats only `HH:MM`, and this is what the sidebar (`SidebarNav.tsx:173`) shows as "last seen". A thread quiet for three days shows "10:42 AM", and messages from different days look the same.
- Fix:
```ts
const fmtTime = (iso: string) => {
  const d = new Date(iso);
  const t = d.toLocaleTimeString([], { hour: '2-digit', minute: '2-digit' });
  return d.toDateString() === new Date().toDateString()
    ? t : `${d.toLocaleDateString([], { month: 'short', day: 'numeric' })} ${t}`;
};
```
- Backend: if `created_at` has no `Z` or offset, `new Date()` parses it as local time and every time is off by your UTC offset. Check this.
- Also check the sort order of `/conversations`. The frontend never sorts (`api.ts:106-110`), so newest-first is assumed.

**8. The dashboard.** `dashboard/page.tsx`:
- **It crashes on a partial response.** A missing `top_queries` throws at line 59, a missing `handover` throws at line 41, and a missing channel object throws at line 22. There is no `error.tsx` in `app/`, so the user gets Next's generic error page. A missing single channel key renders a blank value, not the text "undefined". Merge over defaults in `getDashboard`:
  `const z = {whatsapp:0,instagram:0,facebook:0}; …{ ...d, new_messages:{...z,...d.new_messages}, messages_handled:{...z,...d.messages_handled}, handover:{...z,...d.handover}, top_queries: d.top_queries ?? [] }`.
- **The first impression is a wall of zeros.** A tenant who has connected only Instagram sees WhatsApp and Facebook rows too, and no "Connect WhatsApp" link. Show a card for each connected channel, using the two profile endpoints. Add "Connect a channel" cards for the rest, linking to `/inbox?tab=settings`. If nothing is connected, show one empty state.
- **The window is fixed at 24 hours** (`getDashboard(days = 1)`, `api.ts:129`), with no selector and no refresh. Add a 1 / 7 / 30 toggle. Hold `days` in state and put it in the `useEffect` dependency array.
- **The escalation badge is a different number on each page.** On the dashboard, `PageHeader` puts the sum of `handover` over the window (line 41) into the INBOX pill, which elsewhere means "threads currently NEEDS_HUMAN" (`App.tsx:103`). Same label, two meanings. Pass 0 on the dashboard, or fetch the live count.
- **Metrics are thin.** "All the metrics available" is currently four plain blocks. Missing candidates: total open conversations, the AI-vs-human share, response time, and a trend. Whether these can be built depends on what `/dashboard` returns (backend).
- **The raw error string** (`Failed to load dashboard (401)`) is shown to the user. A 401 should sign out (Fix 2).

## Inbox behaviour (rank 3)

9. **Human takeover reverts within 5 seconds.** `handleToggleTakeover` (`App.tsx:122-139`) only edits local state. The next poll rebuilds `status` from `mode` (`api.ts:102`) and overwrites it. It needs a backend PATCH. Until then, disable the button or label it "preview". `RESOLVED` is unreachable, since `status` from the DTO is ignored.
10. **Sidebar preview says "No messages yet" for every thread except the open one** (`SidebarNav.tsx:151`, `:190`). Messages load only for the open thread. Ask for a `last_message` snippet on `/conversations` (backend), or fetch the newest message per thread.
11. **Every thread shows "CONF: 0.00"** (`SidebarNav.tsx:208`), because `confidenceScore` is never set from the API. Hide it when it is undefined. `unreadCount` and `customerCity` are also never set, so there are no unread markers and the city chip never shows. The header "N ACTIVE" is just `threads.length` (line 67).
12. **Sending errors use `alert()`** (`App.tsx:155`). Show an inline error under the input and keep the typed text.
13. **Minor UX.** Thread cards are `div onClick` (`SidebarNav.tsx:155-158`), so they cannot be reached with a keyboard. Use `<button>`. The login `<label>`s lack `htmlFor` (`login/page.tsx:212`, `:226`), and the inputs lack `autoComplete`. `Header.tsx:165` shows the initials "NP" for every user. While the tenant loads, `Header.tsx:185-192` shows a "LOGIN / SIGN UP" button whose `onClick` is `undefined`, so it does nothing. Render nothing until `currentUser` resolves.

## Meta app review, security and repo hygiene

- **Legal links.** "terms of service" and "privacy policy" (`login/page.tsx:245-249`) are `<span>`s. Meta requires a real privacy policy URL, and a data-deletion URL or callback for Instagram/Facebook login. Add `/privacy`, `/terms` and `/data-deletion` as public pages.
- **Login-page claims.** These are unsubstantiated: "ESTD. 1932", "PRICE 50 PAISA", "FREE FOREVER", "GDPR / Nepal Telecomm Ready", "Meta Graph v21.0 Compliant". Reviewers and search engines read this page, so remove the claims you cannot back up.
- **Unauthenticated routes.** The middleware matcher excludes `/api/*`, so these are public:
  - `/api/meta/webhook` (accepts any POST, no signature check, stores payloads in memory)
  - `/api/meta/webhook-logs` (returns them)
  - `/api/meta/test-connection` (always returns success)
  - `/api/health` (reveals whether `GEMINI_API_KEY` is set and says "SocialSync")
  - `/api/amit`

  The UI never calls any of the `/api/meta/*` routes. Delete `app/api/meta/` and `app/api/amit/`. Keep a stripped `/api/health` that returns only `{status:'ok'}`.
- **Personal data in git.** `conversation_example.json` is tracked and contains real Instagram usernames, IDs and thread IDs. Remove it and rewrite history if the repo leaves your machine. `middleware.ts.bak` and `tsconfig.tsbuildinfo` are also tracked. Add `*.tsbuildinfo` and `*.bak` to `.gitignore`.
- **Proxy and Docker checks.**
  - The middleware reads `BACKEND_URL` at runtime and `.dockerignore` excludes `.env*`. Confirm with a call to `/api/v1/tenants/me` inside the container that it does not fall back to `localhost:8000`.
  - `Dockerfile` sets `HOSTNAME=0.0.0.0`. Behind nginx, check that middleware redirects (`new URL('/login', req.url)`) do not send the browser to `0.0.0.0:3000`. If they do, build the URL from the `x-forwarded-host` header.
  - `middleware.ts:11-13` returns `next()` for `/api/v1/webhooks/`, which becomes a Next 404 if nginx does not route those to FastAPI first.
- **Instagram login in development mode.** Only app roles and testers can log in until the app has Advanced Access. Personal (non-professional) accounts fail. Both show up as `?ig_error=…`. Consider friendlier copy for `access_denied`.

## SEO (when you get to it)

The inbox and dashboard should not be indexed. The inbox is `ssr:false` (`app/page.tsx:8`) and sits behind login, and that is fine. SEO applies only to public pages, and today the only public page is `/login`. Site-wide `title`, `description` and OG data come from `layout.tsx:4-13`. There is no `og:image`, `robots.txt`, sitemap or favicon, and no `metadataBase`.

When ready:
